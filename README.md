## ⚡ Установка

Подключитесь к серверу как **root** и выполните:

```bash
bash <(wget -q -O - https://raw.githubusercontent.com/lidsa-dev/uis/refs/heads/main/setup.sh)
```

Скрипт интерактивный — просто следуйте подсказкам.

---

## 🔥 Что вы получите

### 🔐 Безопасность
- **Новый sudo-пользователь** — вход под root отключается
- **Вход по паролю** — для нового пользователя, пароль задаётся интерактивно через `adduser`
- **Нестандартный SSH-порт** — защита от массовых ботов
- **UFW файрволл** — разрешён только SSH, всё остальное заблокировано
- **Rate-limit на SSH** — автоматическая блокировка при множественных подключениях
- **Fail2Ban** — бан IP на **24 часа** после **3 неудачных попыток** входа
- **Ping отключён** — сервер не отвечает на ICMP, не виден при сканировании
- **13 параметров SSH hardening** — `MaxAuthTries 3`, `LoginGraceTime 30`, `AllowUsers` и другие

### 🚀 Производительность
- **TCP BBR** — алгоритм Google для ускорения сетевых соединений
- **Swap 2GB** — файл подкачки с оптимальными настройками
- **Chrony** — точная синхронизация времени
- **Автообновления** — security-патчи устанавливаются автоматически

### 📦 Дополнительно
- **Docker** — установка в один клик (опционально)
- **Базовые утилиты** — `htop`, `tmux`, `ncdu`, `iotop`, `curl`, `wget`
- **Hostname и часовой пояс** — настройка по вашему выбору
- **IPv6** — опциональное отключение

## 🛠️ Как это работает

```
1.  Обновление системы
2.  Создание нового пользователя (пароль вводится вручную)
3.  Выбор SSH-порта
4.  Настройка файрволла и смена порта
5.  Hardening SSH: вход только по паролю, root запрещён, AllowUsers <ваш_пользователь>
6.  Настройка Fail2Ban (усиленный режим), ICMP, sysctl
7.  Swap, BBR, утилиты, Docker (опционально)
8.  Отключение root
9.  Проверка: вы открываете вторую SSH-сессию и логинитесь по паролю
```

> [!IMPORTANT]
> Придумайте **надёжный пароль** для нового пользователя — это единственный способ входа на сервер.
> Рекомендуется 16+ символов, буквы разного регистра, цифры и спецсимволы.

## 💡 Советы

- **Перед запуском** — убедитесь, что у вас есть доступ к консоли VPS (на случай потери SSH-доступа)
- **Надёжный пароль обязателен** — при входе только по паролю слабый пароль сводит на нет весь остальной hardening. Используйте менеджер паролей
- **Docker + UFW** — Docker обходит файрволл. Используйте `127.0.0.1:PORT:PORT` вместо `PORT:PORT` при запуске контейнеров
- **После скрипта** — если было обновлено ядро, выполните `sudo reboot`
- **Повторный запуск** — скрипт идемпотентен, можно запускать повторно
